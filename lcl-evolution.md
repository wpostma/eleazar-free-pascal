# LCL Evolution Ideas

Changes we want to make to the Lazarus Component Library, tracked with rationale
and current status.

---

## 1. Phased Form Creation (IMPLEMENTED)

**Status:** Done, tested, 10/10 tests pass

Split `EndFormUpdate` into four phases:
1. DeferShowing — set `wcfDeferShowing` flag on all children
2. SetVisible + EnableAutoSizing — handles created, bounds computed, no showing
3. ClearDeferShowing — remove flag
4. UpdateShowing — `gtk_widget_show` called once, after everything is composed

Also: `UpdateControlState` is now a no-op for child controls while parent
form's `FormIsUpdating` returns `True`.

**Files:** `lcl/include/customform.inc`, `lcl/include/wincontrol.inc`, `lcl/controls.pp`

---

## 2. LCL-Only Constraints (NOT YET IMPLEMENTED)

**Status:** Idea — needs design and implementation

### Problem

When you set `Constraints.MinHeight` / `Constraints.MaxHeight` on a form,
the LCL propagates these to the window manager via `gtk_window_set_geometry_hints`
→ `WM_NORMAL_HINTS` → `min_size` / `max_size` in the X11 size hints.

EWMH-compliant window managers like Mutter (GNOME Shell) rigidly enforce
these hints. A window with `min_height = max_height = 85` becomes a
fixed-size panel that Mutter won't let the user drag freely. It snaps,
jumps, and fights the user during move operations.

The Lazarus IDE toolbar needs to be a fixed height (85px) but also needs
to be freely movable. These two requirements are contradictory when the
WM is told about the height constraint.

### Proposed Solution

Add a new property or flag that enforces constraints at the LCL level only,
without propagating to the widget set / window manager:

**Option A: New property `SoftConstraints`**
```pascal
TControl.SoftConstraints: TSizeConstraints
```
Enforced in `DoAllAutoSize` / `RealizeBoundsRecursive` but never sent to
`gtk_window_set_geometry_hints`. The WM sees no constraints.

**Option B: Flag on existing Constraints**
```pascal
TSizeConstraints.EnforceByWidgetSet: Boolean  // default True
```
When `False`, the LCL auto-size system respects the constraints but the
GTK2/Qt/Win32 widgetset backends skip the `SetGeometryHints` call.

**Option C: Platform-specific override in GTK2 backend**
In `gtk2wsforms.pp`, when setting geometry hints, skip the min/max size
if a form flag is set. Simplest to implement, least architectural impact.

### Where the WM notification happens

- `lcl/interfaces/gtk2/gtk2wsforms.pp` — `TGtk2WSCustomForm.SetConstraints`
  calls `gtk_window_set_geometry_hints`
- `lcl/include/wincontrol.inc` — `TWinControl.DoConstraintsChange` triggers
  the widgetset call

### Impact

This would fix the toolbar dragging issue and potentially benefit any
LCL application that wants internal layout constraints without WM interference.

## 3. `poDefault` Centers on Main Form Monitor (IMPLEMENTED)

**Status:** Done, tested

Changed `poDefault` from "let the WM decide" to "center on the main form's
monitor work area." Falls back to primary monitor if no main form exists.

**File:** `lcl/include/customform.inc` — `MoveToDefaultPosition`

## 4. No Synchronous X11 Calls in Signal Handlers (IMPLEMENTED)

**Status:** Done

Replaced `gdk_window_get_root_origin` (synchronous X11 round-trip) with
`gdk_window_get_position` (GDK cache lookup) in `GetWidgetRelativePosition`.

**File:** `lcl/interfaces/gtk2/gtk2proc.inc`

## 5. True Phase Separation in DoAllAutoSize (NOT YET IMPLEMENTED)

**Status:** Idea — large architectural change

### Problem

`DoAllAutoSize` runs all phases (handle creation, bounds computation,
bounds realization, showing) in a single loop that can iterate 100 times.
The `TControlAutoSizePhase` enum exists but provides no actual separation.

### Proposed Solution

Break `DoAllAutoSize` into separate methods that can be called independently:

```pascal
procedure TWinControl.DoCreateHandles;     // Phase 1: allocate widgets
procedure TWinControl.DoComputeBounds;     // Phase 2: calculate sizes
procedure TWinControl.DoRealizeBounds;     // Phase 3: send to widgetset
procedure TWinControl.DoUpdateShowing;     // Phase 4: make visible
```

Each phase completes fully before the next begins. No loops between phases.
GTK signals generated by Phase 3 are queued, not processed synchronously.

### Risk

Very high. Every LCL application and every widgetset backend depends on
the current `DoAllAutoSize` behavior. This would need extensive testing
across GTK2, GTK3, Qt5, Qt6, Win32, Cocoa.

## 6. Don't Mutate Geometry in Resize Callbacks (IMPLEMENTED)

**Status:** Done

`TMainIDEBar.Resizing` no longer calls `DoSetMainIDEHeight`. Height
adjustment happens only from deliberate callsites: `InitPaletteAndCoolBar`,
`MainSplitterMoved`, `CoolBarOnChange`.

**File:** `ide/mainbar.pas`

## 7. Primary Monitor for Default Positions (IMPLEMENTED)

**Status:** Done

`GetScreenrectForDefaults` uses `Screen.PrimaryMonitor.WorkareaRect`
instead of `Screen.WorkAreaRect` (which spans all monitors).

`ValidateAndSetCoordinates` clamps windows to primary monitor work area.

**File:** `components/ideintf/idewindowintf.pas`

## 8. WM Interaction Logging (NOT YET IMPLEMENTED)

**Status:** Idea

Add `{$IFDEF DEBUG_WM}` logging to the GTK2 backend at every point where
the LCL communicates with the window manager:

- `gtk_window_set_geometry_hints` — log constraints being sent
- `gtk_window_move` / `gtk_window_resize` — log position/size requests
- `gdk_window_get_root_origin` / `gdk_window_get_position` — log queries
- `size-allocate` callback — log what the WM gave us back
- `configure-event` callback — log WM-initiated moves/resizes

This would make WM interaction debugging possible without external tools
like `xprop` and `xev`.
